### 全局搜索交互约定与所有权

`preview-search.js` 是独立预览的唯一搜索匹配、结果、分页与命中定位入口；作品与各设定控制器提供当前内存数据，不以当前 DOM 的可见性决定索引。正文包括全部演示章节，练习包括全部题目的当前草稿。当前只有第一部作品提供正文和设定演示，另外两部作品提供可修改的书名、简介与类型。索引以内容字段为单位，每次非重叠出现单列结果，避免同一源内容因列表/详情两个展示副本重复计数。

搜索输入采用 300ms 防抖，组合输入完成或回车立即检索。结果每页 12 处，切换分类或关键词回到第一页；返回页面后关键词保留，再点击搜索栏可继续检索。正文通过选中匹配文字与滚动定位，其余文本通过安全文本节点和 `<mark>` 高亮。高亮使用入口 CSS 变量 `--search-highlight`，共同样式消费该变量；对比度与文字颜色沿用现有墨蓝。索引不收集设置中的 API 密钥或服务配置，不读取外部文件、不发请求、不把关键词写进 URL。

正式产品接入时需要覆盖真实工作区内的全部作品数据与章节内容，再核验文件读取、索引更新和跳转路径。当前预览只验证这一操作方案，不宣称已接入真实数据。客户要求的 Electron 平台目标继续有效。

本方案面向现有中文小说创作工作台。客户已要求正式桌面版由 Tauri 改为 Electron；此前“保留 Tauri”的前提被替代。沿用 React、TipTap、既有作品业务逻辑及当前 Dexie 数据访问设计，重做视觉系统、应用导航、内容布局与公共控件；桌面迁移需单独验证已有工作区与数据兼容。完整平台要求见项目根目录 `DESKTOP-PLATFORM.md`。当前仅完成浏览器设计预览，Electron 迁移尚未实施。

目标：打开作品更直接；写正文时正文占据主要空间；世界观、人物、剧情与资料使用同一套视觉与交互规则；长时间使用依然可读。

## 设计方向

采用从玫瑰粉、杏橙、暖金、青绿、湖蓝、靛蓝到淡紫的连续彩虹环境渐变，半透明导航及一体玻璃写作窗口。主体保持深墨蓝文字，标识采用蓝色，导航选中状态采用浅色玻璃、蓝色图标和左侧标记。彩虹主要体现在环境、标题栏、透明侧栏与状态栏，正文背景约 76–84% 不透明。用环境承载光色，用稳定控件承载操作意义。

Apple 官方材料指南将 Liquid Glass 定位为导航与控件的功能层，并要求克制使用，避免将其施加于内容层。本设计借鉴其控件层次，同时按用户最新要求采用自定义渐变透明窗口。正文背景采用约 76–84% 不透明的连续浅色表面，与外框约 38–52% 不透明的玻璃分开；正文没有动态折射、透视或扭曲，保持文字可读性。

来源：https://developer.apple.com/design/human-interface-guidelines/materials

这是适配现有网页与 Windows 桌面环境的视觉设计。CSS blur、透明度和高光能够近似玻璃层次，但不声称复现 Apple 原生动态折射，也不增加 GPU 滤镜或随指针扭曲正文的效果。

### 材质与平台边界

当前预览中的透明效果体现页面环境渐变，尚未实现 Windows 桌面壁纸透过原生窗口的系统材质。正式实施按 Electron 目标评估窗口背景、拖动区域与 Windows 平台能力。本预览不放置无功能的仿系统关闭、最小化按钮；目录、辅助和专注按钮均实际工作。

原先讨论的深色工作室与纸色书房方向已由用户的浅色选择排除。

## 八个已制作的页面组预览

入口：`docs/redesign/ios26-preview.html`。这是独立设计预览，使用明确标注的示例数据，不接入数据库和 AI 服务，不写入真实作品。

### 作品首页

顶部保留位置与搜索；主区域先给最近编辑作品与“继续写作”，随后列出全部作品。作品卡使用文字书封、题材、简介、字数与更新时间。新建是蓝色主操作，导入是低强调操作。

理由：作者最常见的第一步是回到正在写的作品。让这一步显眼，比在首屏展示所有工具更有效。最近编辑来自现有 updatedAt，不将它冒充用户最近阅读的位置。

### 正文编辑

目录、正文、辅助合并为一个完整写作窗口。统一标题栏显示作品及目录、辅助、专注操作；第二行共享章节路径与格式工具；内部三块区域没有独立卡片外框，用细线与表面透明度差异组织。底部字数和试写反馈贯穿整个窗口。目录与辅助分别可收起，正文在同一外框中扩展；专注模式退出时恢复进入前的面板状态。正文采用 18px 黑体与可切换宋体。右侧参考、细纲、AI 使用统一分段切换。

宽桌面正文在自身区域内滚动，状态栏保持可见。中等窗口辅助区进入同一窗口下方，窄窗口目录变为可横向滚动的章节条，正文与辅助纵向排列；未将三块区域重新拆为独立窗口。

预览使用原生纯文本输入演示实际打字体验，章节切换在本页内保留试写内容与标题；不写数据库，不做持久化。字数来自当前文本，不使用固定“已保存”或虚假字数。B/I 控件明确为全篇字形预览；正式应用仍沿用 TipTap 富文本和既有选区格式能力，不将预览的输入方案替换为产品编辑器。

理由：一体外框表达这些区域共同服务于当前稿件；内部侧栏表达目录与辅助是可调用工具。文字区域的高不透明度保持稳定阅读，外框的透明度提供环境光色和桌面材质感。专注模式不新增数据模型，不改变自动保存逻辑。

### 人物卡

改为人物列表与详情。列表每页 8 位，行高约 65px，不受详情高度影响。支持姓名、势力与设定摘要搜索，全部/主角/配角/反派筛选，以及默认/姓名排序。空结果可一键清除搜索与身份筛选。切换其他页面后保留人物分页与筛选状态；窄窗口将详情排在列表下方。

理由：人物卡的价值是动机与成长线，不是头像装饰。详情保留足够行宽，使长设定便于阅读与编辑。

# 第十五版：核心设定与人物目标

用户要求人物和世界模板仅保留核心资料，并保留由本书灵感拓展的目标与动机。人物表单为姓名、身份、所属、介绍、目标与动机；世界表单为类别、名称、介绍。移除旧扩展字段、重复身份与泛化动机，来源和同步状态继续展示。世界类别覆盖势力、地点、物品、境界、功法、规则、其他。所有初始世界记录、AI 采用记录以及 AI 上下文投影使用同一核心格式。

实际浏览器验证：人物生成能选择两条本书灵感，切换后内容同步变更；补充要求空白也可生成。采用第二条灵感的人物目标后，书内表单可以编辑，修改同步到人物模板。最终精简示例包含要做什么、为什么、推进方向三个部分。删除生成的书内卡片后，模板仍保留目标与动机，标记源卡已删除。搜索人物动机得到源卡和资料库两处命中，源卡结果定位到目标段落。长街来信的人物生成仅提供其自身邮局灵感，未引用修仙作品。

世界观生成以空补充要求返回青云志等势力候选；采用后编辑表单只有三个字段，介绍改为“位于东皇大陆南域，是南域的顶级宗门之一。”后模板同步更新。390 像素窗口人物表单宽 346 像素，页面内容宽 380 像素，无横向溢出；临时尺寸随后重置。浏览器未记录脚本错误。
