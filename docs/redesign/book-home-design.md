# 软件主页与作品首页

用户当前要求：已有页是软件主页；点击一本书，先打开该书的首页；书首页包含灵感窗口和金手指窗口。沿用现有彩虹玻璃风格，继续作为可操作的设计预览。

- 软件主页拥有作品列表、新建、导入与最近作品入口。卡片和最近作品均进入作品首页，软件主页不显示金手指生成按钮。
- 作品首页明确显示书名、简介、类型和原示例统计；提供返回软件主页。首部作品保留现有正文演示的继续写作入口，其他作品的正文及人物等完整工作区尚未改为独立数据，不能宣称已完成全工作区多作品隔离。
- 第十四版将人物和世界观两类书内卡片按作品 ID 隔离，并同步到公共资料库。其他示例书这两类源卡初始为空，可自行创建。正文、大纲等其余模块仍未完成完整多作品隔离。
- 灵感和金手指由两扇并列的模块窗口承载，900px 以下上下排列。窗口内是可滚动的紧凑条目，完整内容可在共享表单查看／修改。空窗口保留新增和 AI 入口。
- `preview-books.js` 唯一拥有作品信息、当前作品、每本书的两类记录、手动新增／修改、AI 采用与撤销接口。记录按稳定的作品 ID 分开，书名修改不改变记录归属。不得以改变面包屑或标题模拟数据隔离。
- `preview-ai.js` 继续唯一拥有 AI 条件、候选、采用、撤销与失败流程。作品首页入口捕获当前书 ID；采用留在该书窗口，反馈注明书名。其他既有页面流程保留。
- 原生 dialog、input、textarea 继续承担焦点、键盘与多行输入。表单标题与内容必填，错误保持输入；取消和 Escape 不保存，关闭后返回原入口或重建后的同一条目。
- `preview-search.js` 仍是唯一全局搜索。索引包含每本书的灵感与金手指；点击命中切换到对应书并定位原条目，不能只打开当前书。
- 作品首页 URL 使用 `view=bookhome&book=<id>`。刷新恢复对应示例书；仅本页新建的书刷新后不存在时返回软件主页并明确提示。
- 所有采用和手动修改仅在本页保留，刷新恢复。真实数据库、AI 服务与 Electron 集成不在本轮实施。

验证结果见 `2026-10-03-design-review.md` 的第十版记录。

第十三版补充：灵感定义为整本书的主线前提，核心是“主角获得什么金手指，要完成什么目标”。页面提示、手动录入提示及示例候选采用此定义。原有零散场景的示例记录改成整书故事种子。书名／简介／大纲最终应承接选定的核心灵感；当前只完成灵感内容形态，尚未接通该依赖链或从灵感开书流程。
