# 写作台：文风提炼、规则技巧与生成审核设计

状态：供用户审核的设计稿，尚未接入真实AI或改写预览生成器。依据：用户本轮提供的流程与此前确认的练习、核心灵感、核心卡片、章节状态、人工纠错要求。目标是优先提高个人文风提炼的可靠性，再将有效结果用于生成；不新增重复页面，不扩张人物或世界观表单。

## 1. 四类资料必须分开

| 资料 | 作用 | 来源与启用 |
|---|---|---|
| 故事事实与计划 | 约束剧情、人物目标和当前状态 | 本书灵感、金手指、当前章节事实、独立计划；已发生与计划分开 |
| 作者文风档案 | 描述作者在不同任务下的真实表达习惯 | 作者原创样本、逐篇AI分析、人工修正版、留出验证；待验证结论不作硬要求 |
| 写作技巧 | 提供可选的正向写法 | 拆书原文与报告、作者自定义；按本次任务选用，不全部注入 |
| 避雷规则 | 提醒作者明确不喜欢的表达 | 被标记片段、原因、作者修正；适用范围和例外必须保留 |

外部人类文章可作技巧或目标风格参照，不能混入作者原创样本来提炼个人文风。作者设定了目标风格时单独记录，不改写其观察档案。不得为了风格主动增加世界事实、改动人物动机或把未来计划当成已发生。

## 2. 文风提炼：主流程

原创练习 → 正文统计 → AI逐篇语义分析与原文证据 → 作者修正分析 → 从已审核样本提炼候选文风 → 分组留出验证 → 作者审核累计结论 → 文风档案版本。

六个维度保持用词、句式与节奏、描写、对话、情绪、叙事。每条结论需包含原文证据、作品及版本、题材与任务、支持和反例、适用范围、人工修正、状态。样本不能观察某个维度时记为不可观察，不当反例。

审核动作是准确、修改分析、删除错误结论、暂时无法判断。修改后保存AI原结论与人类修正版，不改练习正文。说明选填；若用户不愿提供正确答案，删除或不确定仍可保存。修正单篇分析与审核累计文风是两个明确入口，不要求作者重复审核没有变化的结论。

下次逐篇分析读取相关已审核纠错案例和档案，显示参考记录。选择依据为相同维度、任务及适用题材，不按简单点赞数量覆盖原文。分析先引用新文章证据，再说明旧判断是否适用；不能只复述档案。

反馈通过上下文示例影响下一次调用，不宣称模型权重自动学习。人工纠正具有可修订版本；互相冲突的修正不静默合并为全局规则。

### 留出验证

1. 同一练习/作品的段落、改稿、相近复制样本按来源分组，不能分散到提炼集和验证集。当前预览仅去空白完全重复排除，近似重复检测为新增设计。
2. 样本少先标待观察。有足够可观察独立作品后留一作品组，其余作品提炼，再检查被留作品；各轮结果分别保留，不将重叠轮数当独立证据。
3. 共同文风再留出整个题材；其他题材提炼后，检查留出题材。同题材出现不同写作任务时也检查任务范围，避免把命题要求当作者习惯。
4. 用新近作品前向验证旧档案，识别随时间变化；不能用未来反馈帮助旧结论通过检验。阈值、提示词、规则调整不能根据最终测试集反复调优；另设开发集，反馈使用后该样本不再是未见测试样本。
5. 多评审只在重要语义分歧时追加。每位先独立给证据，不能看到他人结论后跟投票；多数票是复核线索，不能替代原文、人类修正或样本验证。

### 函数工具与读数

可计算句长中位数、分位数及离散程度、段落长度、引号占比、重复n-gram、经人工确认词表的命中位置。中文形容词/副词比例需要分词与词性标注并核验误差；引号不能直接等同人物对话。句长标准差低只表示均匀，不能推出AI生成或质量低。

对每条候选分别展示：

- 支持率 = 支持该候选的可观察留出作品数 / 可观察留出作品数。
- 覆盖率 = 可观察留出作品数 / 全部留出作品数。
- 反例数与不可观察数，附原文。
- 人工纠正率 = 被作者实际修改或删除的结论数 / 被作者完成审核的结论数；不确定另列，不进入分母。
- 已知同类误判复发 = 新样本中再次被人工确认的同类错误数 / 新样本中被人工审核的该类判断数。

分母为0显示暂无数据；小样本显示计数和范围，不显示虚构准确率。结论出现率与人工一致性不是AI正确率，不合成无标定的总分。对完整档案采用作品组重采样检查稳定性为后续选项，样本不足禁用；不得把相关样本当独立观察。

生成使用文风档案中的范围、代表性原文、自然语言说明及统计区间；不强制每段达到同一比例。不设通用文风距离达标阈值，未校准距离仅作对比线索。未审核、被否决或过期结论不当硬约束。

## 3. 写作技巧与避雷规则

技巧模板：名称、适用情境、可执行动作、原文例子、效果解释、例外。例：“需要隐瞒情绪时，先写一个人物能控制的动作，让对话与动作形成反差。”不能笼统要求每句话都用动作替代情绪。

避雷模板：问题片段、作者不喜欢的具体原因、适用范围、建议替换方向、保留例外、状态。例：“本书紧张追逐中避免插入无关的总结升华；角色主动思考后果时允许概括。”不把首先、然而、因此列为一律禁用，不把作者自己的排比与长句当错误。

提炼及合并保留来源、否定方向和范围；同主题正向技巧与负向禁忌不能互相覆盖；冲突条目交作者选择。新规则先作为建议，不能因模型自行提炼即全局启用。

## 4. 对应现有功能

| 位置 / 现有操作 | 必须参考 | 主要检查与修订 |
|---|---|---|
| 灵感 `ideas` | 题材、指定元素、选填要求 | 概括主角获得何种金手指方向及要做什么；不详写金手指、不写成章节；审核主线是否清晰，不强加个人正文文风 |
| 金手指 `golden` | 本书核心灵感、主角、选填要求 | 详细拓展能力与限制，遵守主线；冲突处定位修改 |
| 书名简介 `book` | 已确认核心灵感为主，相关本书设定为辅 | 不发明另一条主线；检查内容契合、简介泄露范围与表达；不恢复被要求删除的重复入口 |
| 人物 `person` | 核心灵感及当前章节事实 | 姓名、身份、选填所属、介绍、目标与动机；主角要做什么、为什么；不能强制无势力人物加入势力 |
| 世界观 `world` | 类别、已有同类设定、当前事实 | 仅类别、名称、核心介绍；同名身份、物品归属、已灭势力状态检查；未知不补成事实 |
| 大纲及章纲 `outline` 等 | 灵感、目标、金手指、事实与计划、此前纲要 | 因果、目标推进、代价、重复事件、伏笔；改未来计划不覆盖已写章节；不把文风句长强套在提纲 |
| 正文 `continue/full` | 本章纲、章节时点状态、相关前文、选定技巧、已审核文风与避雷 | 结构与事实检查＋轻量文风复核；生成1稿为默认，多候选由用户选择 |
| 选区 `polish/expand` | 当前选区、邻近上下文、本书事实、作者原文风格 | 只处理指定范围；润色保留含义，扩写允许细化动作但不得私改关键事实；差异预览 |
| 摘要 `summary` | 已写正文 | 引文与事件依据、遗漏、计划混入；摘要不修辞性模仿正文 |
| 练习与档案 `preview-practice.js` | 原创正文、题材任务、历史纠正 | 六维分析、人工编辑分析、分组验证、累计文风；不替作者重写练习来“提高通过率” |
| 拆书 `passage/bookAnalysis/textAnalysis` | 实际提供的片段及取样范围 | 引文可定位，区分片段观察与全书结论；样本不足不能声称整书特点 |
| 技巧 `tips/techniques` | 拆书证据与作者选定技巧 | 可执行、范围及例外；参考作品技巧不混入个人文风事实 |
| 避雷 `rules/mergeRules` | 标记片段与人工原因 | 保留用户偏好、来源、范围；去重复而不丢冲突及例外 |

## 5. 生成后的闭环

读取本次资料快照与版本 → 生成 → 确定性检查 → 按任务进行语义审核 → 显示具体问题及证据 → 局部修订 → 重查受影响约束与上下文 → 作者采用。

审核结果需含对象版本、问题位置、原文、违反的规则/设定来源、问题说明、修改建议、严重程度。函数验证JSON结构、必需字段、字数约定、引文和补丁范围；实体别名、时间线因果与状态变化需要结构化事实和语义判断，不能假称均可用正则确定。

分成阻止采用的结构/事实冲突、需作者确认的语义矛盾、可选风格建议。风格建议不自动阻止生成；作者认可的正文特点不因通用“去AI味”清单被强改。

默认一稿一轮审核与局部修订，然后终验；仍有严重问题或资料不全则交作者处理，不无限重试。作者选择严查或多候选时预先说明额外调用。取消、失败、模型迟到回包均不能覆盖原稿；采用前校验书籍、章节、选区及设定版本仍匹配，保留差异和撤销。

局部修订只能基于确认事实补充具体细节，不允许为了像人捏造个人经历、数字或世界设定。“去AI味”对外以重复表达、空泛细节、节奏、风格偏离等可解释问题呈现，不输出AI来源概率。盲测只辅助比较自然度和作者风格匹配，不据此保证作品质量或证明人类来源。

## 6. 建议的接入顺序与验收

第一步沿用交互预览：把练习审核改为编辑分析，留存AI原文和人类修正版；累计档案展示验证依据、范围和修正来源。第二步补技巧、避雷条目的作用范围及状态，生成窗口显示本次选用的资料。第三步接真实AI分析、反馈检索和留出验证。第四步将已审核档案接入正文生成的审核、局部修订及终验。

验收必须包含：修正版被下一轮实际请求引用；旧版及跨书数据不误用；题材限定不会升级为全局规则；反馈没有泄入留出测试；否决结论不再作为生成要求；审核失败原稿完整保留；修订未碰选区外正文；统计检测不能宣称AI来源；规则冲突能解释并让作者决定。

当前预览已有正文统计、版本、反馈选择、整篇与题材规则验证，但尚无语义分析修正版回流。旧正式源码 `src/features/ai/contextBuilder.ts` 已有核心灵感、技巧、文风、避雷的注入位置；接入应延续这些位置，不能新建一套互不相通的提示词链。现有26项演示生成不代表真实模型质量闭环。

## 研究依据

- 分组留出避免同组在训练/测试同时出现：[scikit-learn GroupKFold](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupKFold.html)。本设计将这一思想用于作品及题材分组，不表示项目已引入该库。
- 模型评审存在位置、冗长及自我偏好：[Judging LLM-as-a-Judge](https://arxiv.org/abs/2306.05685)。多角色提示不能保证独立评审，更不保证准确。
- 用户粘贴的文章类型收益等级、调用收益递减轮数和“接近随机即成功”未获本项目实测，不作为产品承诺或验收阈值。
