# 写作台桌面测试版实施计划

用户已授权完成剩余功能直至打包前，不制作安装包、不发布。

目标：沿用最新彩虹玻璃界面与已确认流程，将现有模块化界面接入 Electron、安装目录 SQLite 和真实 AI。旧 React/Tauri 源码保留作为迁移来源，不再作为新桌面入口。采取这一方案是为了避免重写已经验收的新版交互，也不把旧 IndexedDB 当作正式数据源。

采用 superpowers 的实施计划与子任务执行工作流，各任务先做验证再合并检查。视觉继续遵循 Frontend Design Premium 及 DESIGN.md。

## 边界与接口

- 新桌面入口在 desktop/，构建产物在 desktop/dist/。开发库在项目 .desktop-data/，已安装环境根据 process.execPath 解析可执行文件同级库。
- 主进程负责 SQLite、文件对话框、密钥保护与 AI HTTP 请求；沙箱预加载只暴露有限业务 API，renderer 不获得 Node、路径或任意 SQL 执行能力。
- window.desktop.bootstrap() 同步返回 {snapshot,settings,info}；save(snapshot) 和 flush(snapshot) 保存完整业务快照；KV 兼容练笔现有同步保存，但最终只入 SQLite。所有保存带版本，失败不能宣称成功。
- 生成接口 generate({requestId,operation,values,context}) 返回候选数组；cancel(requestId) 中止请求。setAIConfig/getAIConfig 保护密钥，testAI 实际验证。真实服务需要用户自己填入配置，不消费已有未知凭据。
- 初始无作品，资料技巧可内置。书内人物、世界观、大纲、正文、剧情场景、卡片选择按稳定作品 ID 隔离。全局搜索跨所有作品。
- 所有语义结果必须有依据并由作者确认。正文/伏笔采用和撤销同一快照事务。生成前读取章纲、近章有效摘要、前章末尾、当前卡片、灵感金手指、适用技巧规则和经人工审核文风。
- AI 文风与剧情检查使用独立提取/验证，分歧不伪装成确定结论；人工修正供下次参考，不声称微调模型。
- 发布前保护构建删除 source map、混淆业务脚本、生成完整性清单。完整性用于检测改动，无法保证客户端不被破解。不创建安装包。

## 本轮收尾记录

- 修复新建作品未选中、换书沿用待导入/导出选择、导出旧正文、第二卷章纲与正文目录关联、示例字样残留。
- 应急导出允许直接另存当前内存快照与失败的练笔/阅读写入，不要求先成功保存数据库。永久保存失败限制自动重试，关闭失败保留窗口。
- 公共模板独立保留初始/最新版本。旧章节数据库 ID 改为保留 legacyId，正文序号按作品内次序生成，关联稳定章纲 ID。
- 文风训练只读取本版人工确认/修正的观察；每条跨作品判断必须至少两篇不同训练正文的引用。重新分析保留旧审核历史，但新结论重新等待人工核对。
- 默认单个 AI 创作、独立调用审核与局部修订。共同推演仍是待比较的研究方向，没有新增并行或集群运行架构。
- 数据和窗口测试使用隔离数据库与本机 HTTP 响应；自动测试不调用用户未知密钥、不修改用户作品。
